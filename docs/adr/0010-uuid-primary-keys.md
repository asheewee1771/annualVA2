# UUID primary keys

Status: accepted

Every table uses a `uuid` primary key, generated by the database (`gen_random_uuid()`), and exposes it in URLs. Sequential ids would reveal volumes and invite enumeration, and the org standards require UUID keys. A user's id is the only identifier that may appear in logs (`user.id`), never an email.

Consequences: ordering uses `created_at`; the business System ID from the System Register stays a separate natural key; foreign keys and audit references are uuids.
